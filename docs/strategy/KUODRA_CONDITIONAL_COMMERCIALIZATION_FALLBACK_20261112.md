# KUODRA — KIC 본선 미진출 시 크몽 등 독립 상품화 전환 계획

**기록:** 2026-11-12 KST · **지시:** 사용자 "만약에 못 올라가면 우리 상품화하자. 깃헙에 적어놓고" · **상태:** 조건부 전략/개발 대기 · **제품:** KUODRA (독립 투자 리서치·공시 검증 Agent)

## 1. 발동 조건과 원칙
- **2026-12-03 예선 결과**에서 **본선 미진출이 공식 확인되는 경우** KUODRA를 해커톤 독립형 상용 제품으로 전환하는 계획을 우선 검토·착수한다. 결과 발표 일시는 대회 공식 사이트에서 당일 재확인한다. 현재 탈락/진출은 어느 쪽도 확정되지 않았다.
- 본선 진출 시 [기존 본선 실행 계획](../architecture/KUODRA_FINALIST_EXECUTION_ROADMAP_20261112.md)을 우선하며, 이 상품화 계획으로 자동 전환하지 않는다.
- 본선 탈락은 기술 실패나 실제 제품 검증 불합격을 의미하지 않는다. 심사 순위와 판매 가능성은 별도 평가한다.
- 기존 코드, 제출 당시 원본, 유효한 A/B/C/Guard/데이터 정규화/AutoML 설계를 보존한다. 무단 코드 공개 변경·라이선스 변동·유료 계약·Production 배포 금지.
- **0원 유지비 목표**, 사용자 질의응답과 설치 지원을 최소화할 수 있는 독립 실행형 상품을 우선 검토한다. 외부 데이터·모델·호스팅·마켓플레이스 수수료까지 무조건 0원이라고 보장하지 않는다.
- 현재 제품은 검증된 내부 엔지니어링 범위 **82/100**, `RELEASE HOLD`; 판매 가능한 완성품 아님. [최종 제품 범위](../architecture/KUODRA_UNIFIED_ANALYTICS_FINAL_SCOPE_20261109.md) 및 REQUIREMENTS/STATUS/HANDOFF가 완성률 기준이다. 상용 판매 적합성은 별도의 법적·고객 수용 게이트로 평가한다.

## 2. 고객과 가설 — 판매 전 검증 필수
- **초기 고객 가설:** 증권 리서치가 필요한 소규모 기업/개인 연구자, 재무·회계 분석 실무자, 기업공시·비재무 주장 검증 담당자. 금융투자회사·규제기관의 공식 승인이나 성과는 주장하지 않는다.
- **핵심 가치:** 사용자가 보유한 합법적 공시/CSV/SQLite/PDF/DOCX를 오프라인으로 분석하여 자산·기업 기본정보, 이상 신호, 출처·기간·불확실성, Guard 및 다운로드 가능한 보고서를 제공한다. **판정 근거가 없는 전망·매수/매도 추천·자동 주문·투자수익 보장은 제외**한다.
- **첫 판매 가능한 최소 제품 (MVP):** (1) 고객 자신의 Windows PC 또는 내부망에 로컬 설치 (2) 승인된 로컬 파일 입력, 필요시 권리 확인된 공개 소스만 선택형 (3) 단일기업/자료 검증, A/B/C 해당 가능한 영역과 Guard (4) 출처가 붙은 PDF/HTML 분석 보고서 (5) 오프라인 도움말·샘플·실행 오류 리포트.
- 사용자 원천 데이터의 서버 업로드가 기본 동작이 되지 않도록 하고, 툴 호출 실패·근거 부족은 `UNAVAILABLE`/`HOLD`, 합성 샘플은 `SYNTHETIC_FIXTURE`로 표시한다. 인증된 금융의견으로 포장하지 않는다.

## 3. 상용화 아키텍처 선택 — 비교 후 채택

| 대안 | 비용 | 개발 속도 | 유지보수·보안 | 잠정 판정 |
|---|---|---|---|---|
| A. 고객 PC 로컬 실행형 Windows 패키지 + 오프라인 파일분석 | 외부 호출·서버 상시비용 최소 | 기존 Python/Streamlit/SQLite 재사용 가능 | 고객 PC별 설치·OS 테스트 필요; 데이터 외부 전송 예방에 유리 | **우선 추천** |
| B. 고객 보유 인프라에 자체 호스팅(온프레미스) | 고객의 서버/운영비가 발생할 수 있음 | 기업 고객 범위 확대 가능 | 배포·인증·IAM·보안 책임 상승 | 선택형 확장 |
| C. 제공자 운영 웹 SaaS + 외부 유료 시장 데이터 | 호출/트래픽/라이선스 상시 비용 증가 | 공개 데모 접근 쉽지만 생산 운영 진입 장벽 | 민감 자료/저작권/보안/고객지원 부담 높음 | 초기 범위 제외 |

**선택:** A를 기준으로 단일 기업 요청형, 로컬 우선, 데이터·모델 제공자 플러그인 형태로 단계별 구성. 고객이 정당한 외부 라이선스를 확보하는 경우에만 B 또는 권리 확인된 외부 연동을 지원한다. 실제 구현 전 설치 경험, 비용, 성능을 비교해 최종 승인받는다.

## 4. 데이터·코드 라이선스·법적 책임 게이트

1. **Massive:** 2026-11-10 사용자에게 전달된 공식 영업 답변에 따라 Free/Individual은 개인·비상업·비업무용이고 제3자 제공·외부 전시는 Business 권리가 필요하다. **이 플랜 원천/파생 시장 데이터의 고객 전달·상품 데모·재배포 사용 불허로 취급**한다. 유료 전환도 별도 사용자 승인 전에는 하지 않는다.
2. **SEC·발행사 공시·DART 등:** 접근 가능한 공식 공시라고 해서 모든 콘텐츠·API 조회·상업적 재배포가 자동 허용되는 것은 아니다. 데이터 이용 약관·출처 표기·저장/재전송·rate limit를 확인한다. SEC 403/429는 우회하지 않는다.
3. **NDX·FRED의 제3자 지수 데이터·KRX 등:** 원천 공급자뿐 아니라 거래소·기초 지수의 별도 저작/전시/파생 데이터 사용권 확인 없이는 제품에 번들하지 않는다.
4. **사용자 제공 데이터:** 구매자가 적법하게 보유하고 처리 권한이 있는 파일을 **로컬 분석**하는 구조를 우선한다. 사용 허락·보존·삭제·오류 로그·결과 리포트 접근 범위를 명시한다.
5. **GitHub 원본 소스 공개 상태:** 현재 저장소는 공개로 보고되어 있다. 별도 최상위 LICENSE 파일은 현재 루트 목록에서 확인되지 않았다. 소유권, 종속 라이브러리·AI 모델 라이선스, 기여 코드·공시 데이터의 재사용 조건과 OSS 고지/상업적 배포 가능 여부를 **실제 코드·의존성 전수 감사**해야 한다. 공개 저장소 코드를 무단 비공개로 바꾸거나 기존 공용 버전/기여자의 권리를 소급 박탈하지 않는다. 판매 보호는 지원·설치 패키징·품질·고객 경험 등 정당한 가치에서 찾는다.
6. 투자자문/투자정보 서비스 적용 법령·표시광고·면책·개인정보 처리·마켓플레이스 판매 요건은 판매 전 대한민국 기준으로 별도 확인한다. `분석도구` 표기만으로 규제 면제가 보장되지는 않는다.

## 5. 개발·검증 단계 (일정은 결과 확인 후 산정)

## 6. 상품 구성·판매 전략 (제안, 미확정)

- **BASIC:** 기업 공시/고객 제공 문서 단일 파일·기업 기본 검증, Guard와 근거 리포트. 유료 외부 API 없이 사용 가능한 범위만 제공.
- **PRO:** 다중 자료 비교, A/B/C 통합 분석, 추가 통계/자동화, 보고서 템플릿 등 **실제 검증 완료된** 기능에 한해 제공.
- **BUSINESS(추후):** 고객 자체 인프라·역할권한·내부 설치, 기관 자료 권한 및 별도 계약에 의존하므로 기본 판매 약속하지 않음.
- 고객이 구매할 이유: 직접 설치·실행 가능한 패키지, 검증 가능한 근거, 오프라인 개인정보 보호, 오류 복구·문서화·검수. 단순 오픈소스 코드 포장만으로 독점·차별성을 주장하지 않는다.
- **가격은 미정:** 기능·유지지원 범위·경쟁상품·고객 인터뷰/크몽 정책 확인 후 정한다. 시장 수요/구매 전환율 근거가 없으므로 매출 기대를 보장하지 않는다.
- 상품 설명·FAQ·샘플 리포트·자동 안내를 제공하여 사용자/구매자의 질의 부담을 최소화한다. 단, 설치 환경과 금융 데이터 권리 확인 같은 필수 지원을 제거한다고 약속하지 않는다.

## 7. 시작 순서·소유자 승인 사항
1. 2026-12-03 공식 본선 미진출 확인 후 최신 `HANDOFF.md` → `STATUS.md` → `AGENTS.md` → `REQUIREMENTS.md` → 실제 코드 순서로 검토한다.
2. 현재 코드·데이터·테스트/CI/프로덕션 상태와 라이선스/의존성 전수 감사, 원본 백업 및 복구 가능성 확인.
3. **상품화 2안 이상** 성능·비용·유지보수 비교로 목표 고객, SKU, 최종 100% 스펙과 출시 게이트를 확정하고 사용자 승인받는다.
4. 원본 수정 없이 분리된 허가된 브랜치에서 점진 개발→테스트→패키징→사용자 최종 승인 후 판매 등록.
5. 주요 개발·검증 완료 시 `STATUS.md`, `HANDOFF.md` 및 필요할 경우 해총 `kmong-productization`에 **검증된 수치만** 반영. 다른 채팅이나 저장소의 최신화는 자동 동기화되지 않는다.
