# KIC 작업 순서 최적화 · 선행 작업 허용 (2026-10-24 사용자 승인)

상위 정본: https://github.com/hibi89/hackathon-command-center-2026/blob/main/docs/WORK_ORDER_FLEX_POLICY_20261024.md

## 실행
1. `lead/kic` 최신 HEAD, `LEAD_ACTIVE_WORK.md`, `DAILY_PROGRESS.md` 및 원본 `DAILY_CAPACITY_PLAN_20261024.md`를 먼저 확인한다.
2. **당일 검증 기준 100% 달성 후, 다른 날짜의 READY 작업으로 바로 이동 가능**. 날짜 순서는 절대적이지 않다. `ㄱ`는 다음 **실제 실행 가능한 최우선 단위 작업** 실행.
3. 마감 단축·선행 의존성·독립 검증 가능성을 우선. 막힌 DAKER 사이트/권한, DART 원문 뷰어 직접 확인은 증거 전까지 `BLOCKED` 유지; 가능한 Research/Verification/Risk 오프라인 과제는 구분 개발.
4. 현재 Research 선행 완료·10/28~30 및 11/02 관련 증빙/테스트는 **재구현 금지**. 최신 포인터의 독립 Risk 검증 단위부터 진행 가능. 선행 작업은 각 원래 예정일과 실제 수행일을 기록한다.
5. 당일 계획의 100점과 미래 과제의 100점을 분리한다. 선행 완료가 오늘을 100% 초과시키거나 BLOCKED 분모를 희석하지 않는다. 완료 선언은 실제 테스트/커밋/CI에 근거하고 수동 재무 검증을 공식 DART API 실검증으로 오인하지 않는다.
6. `DAILY_PROGRESS.md`·필요시 `STATUS.md`, `HANDOFF.md`, `TO_HACKATHON_LEAD.md`에 날짜/작업ID/변경 이유/선행조건/차단/테스트/원격 SHA/남은 기본·예비시간을 등록한다. 실제 측정되지 않은 시간을 만들어내지 않는다.
7. **변경 금지:** 예선 마감, 승인된 60일 날짜별 계획, 기준 품질, 비용 0원 정책, 실데이터/권한 승인 게이트. 외부 접근 지연 시간은 `UNKNOWN` 별도.

**한 줄:** 일정표는 원래 계획을 보존하고, 실제 실행은 선행조건을 만족한 작업부터 최적 순서로 진행한다.
