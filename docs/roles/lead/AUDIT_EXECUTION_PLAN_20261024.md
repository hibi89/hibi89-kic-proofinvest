## 2. 최적 실행전략 — 두 대안 비교

| 비교 | A: 예선 전에 웹 완제품 개발 후 기획서 | **B: 심사 기획서 + 세 기능 최소 실행 증거 병행 (권고)** |
|---|---|---|
| 본선 진출 관점 | 데모 성공 시 실현성 강점, 실패 시 기획서 품질·제출 위험 | 문제·Agent 설계·차별성 설명과 실제 테스트 증거를 균형 있게 확보 |
| 개발비용/API | 인증·배포/LLM 모델비용 증가 가능 | 우선 합성/무료 도구, 승인된 최소 실제 데이터만 검증 |
| 속도·장애 위험 | 미검증 API·UI 병목과 통합 위험 높음 | 계약→독립 기능→검증 가능한 CLI 연계로 복구 용이 |
| 유지보수 | 빠른 UI 중심 구현이 결합도를 높일 수 있음 | 출처/수치/위험 데이터 계약을 고정하고 이후 UI 추가 |

**B안을 KIC 일정의 운영안으로 사용한다.** 예선 전 **작동하는 오프라인 증명 + 10페이지 기획서**를 목표로 한다. 웹 UI와 Production은 가능 시 가점용 보강이며 예선 마감에 대한 필수 선행조건이 아니다. **3개 확정 기능 범위는 축소하지 않는다**. 별도 사용자 승인이 필요한 공통 스키마 확정·외부 API 실호출·지출/권한/보안 변경을 승인한 것으로 간주하지 않는다.
