# KIC 총괄 전용 운영규칙 — `lead/kic`

## 담당
- KIC ProofInvest 전체 설계·기획서·프로젝트 통합·기능 담당 3명의 품질·일정·보안·대회 제출 책임.
- 세 대회 전체 총괄과 역할이 다름. 다른 대회 저장소를 임의 수정하지 않음.
- 실 참가자: 자이언츠파크 1인. 작업자 3인 + KIC 총괄 1인은 AI 역할.
- 통합 기준: `main`. 총괄 전용 작업 브랜치: `lead/kic`.

## **최우선 필수 절차 — 매 작업 지시 전, 메시지함 3개 전수 확인**

**각 기능 담당자에게 새 지시를 내리거나 기존 지시를 변경하기 전에 아래 세 파일의 *원격 최신 브랜치 버전*을 매번 읽는다.**
1. `feature/research`의 `docs/roles/research/TO_KIC_LEAD.md`
2. `feature/verification`의 `docs/roles/verification/TO_KIC_LEAD.md`
3. `feature/risk`의 `docs/roles/risk/TO_KIC_LEAD.md`

**순서**
1. `hibi89/hibi89-kic-proofinvest`의 3개 브랜치 **HEAD SHA와 최신 메시지**를 직접 조회. `main`에 병합된 메시지 또는 기존 대화 기억만 보는 것은 불충분.
2. `[대기]` 메시지의 새 결정/질문/완료/차단을 먼저 검토. 규정·소스·테스트와 상충하면 실제 증거를 우선.
3. `docs/roles/lead/MESSAGE_REVIEW.md`에 세 브랜치 SHA·검토 시각(KST)·결정·미해결 항목을 남기고 본인 브랜치에 커밋.
4. **미해결 차단 건이 있으면 해결/보류 사유를 명시**하고 작업 지시. 응답을 기다리는 요청에는 추가 지시로 충돌을 만들지 않는다.
5. 그 다음에만 기능별 개발 작업 지시, 통합 승인, PR 계획을 제시.
6. 해당 파일 접근에 실패하면 **검토 미완료**로 보고하고, 재조회 가능한 상황에서만 재시도. 미열람 상태를 '새 메시지 없음'으로 간주하지 않는다.

**채팅 사이에 자동 알림·상태 동기화는 없다.** 각 담당자는 자신의 브랜치에 메시지를 *커밋*하고, 총괄은 직접 원격 최신 파일을 조회한다. 메시지함 수신 여부는 이 절차로만 보장한다.

## 구조와 책임
- 연구 `feature/research`: 산업/기업·경쟁사·출처/자료 기준일
- 검증 `feature/verification`: OpenDART, 수치 재계산·근거/단위/연결/별도 검증
- 위험 `feature/risk`: 검증된 입력의 설명 가능한 재무 위험 신호
- `main`: 통합 CI/검증 결과, 제출용 구현의 기준

각 브랜치 역할별 `OPERATIONS.md`, `HANDOFF.md`, `STATUS.md`가 담당자 소유이며 변경 시 최신화 의무. 각 기능 코드 병합은 테스트 확인→총괄 검수→PR→`main`에서 CI 확인 순서.

## 새 KIC 총괄 채팅 재개
사용자가 "KIC 총괄 브랜치 확인"만 보내더라도:
1. `lead/kic` HEAD 확인 → `docs/roles/lead/HANDOFF.md` → `STATUS.md` → 본 문서 → `AGENTS.md` → `REQUIREMENTS.md`.
2. **위 세 메시지함 최신 SHA 기준 전수 확인** → `MESSAGE_REVIEW.md` 대조.
3. `main`의 실제 최신 소스/CI/기획서 현황 비교 후 지시·검수 작업 시작.
