## 과소추정 재발 방지 산정 원칙
- 사용자 관찰: 이전에 4시간이라 예상한 일이 실제 8~20시간 걸렸다. 같은 실패를 방지하기 위해 기본 산출물을 기존 대형 과제의 약 1/3 이하로 쪼개고, 1~2h 범위의 좁은 작업 하나만 매일 배정한다.
- 기본 예상은 코드 작성뿐 아니라 해당 작은 작업의 1차 시험까지 포함하는 작업 계획 시간이다. 검수·실패 대응·환경 복구를 별도 예비로 더한다. 대부분 날 **기본 1~2h + 예비 2~3.5h = 최대 3~5h**. 총합은 근무 의무시간도 아니며 예측 보증도 아니다.
- AI 작업 대기시간·외부 사이트 접속·사용자 실제 계정 확인·의존성 승인으로 소요가 달라질 수 있다. KIC가 하루 8~20h를 혼자 쓸 수 있다는 전제는 금지한다. 세 대회 병행으로 사용자 집중 시간이 부족하면 해당 일에 바로 재산정한다.
- 같은 오류가 2회 반복되거나 일 상한에 도달하면 미완료로 기록하고 **작업을 잘게 분할해 다음 날짜로 이월**한다. 공통 기능을 삭제하거나 검증 없이 DONE이라고 주장해 일정을 맞추지 않는다. 기본 예측의 두 배를 넘는 실측이 나오면 다음 3일의 기본/예비를 즉시 재산정한다.
- 가장 높은 우선순위는 **DAKER 권한·공식 PDF 원본 확보 → 10쪽 이하 기획서 → 11/10 접수 영수증 → 코드 개선**. 11/08 이후 신규 개발을 PDF보다 앞세우지 않는다. 실 OpenDART/LLM, 데이터 계약 최종 확정, 실 금융자료 외부 전송, 신규 지출은 사용자 허가 없이는 하지 않는다.
- 주요 작업을 마칠 때마다 이 문서의 맨 아래 실측 기록과 LEAD_ACTIVE_WORK/STATUS/HANDOFF/TO_HACKATHON_LEAD를 함께 갱신한다. 진행이 없었다면 형식적인 커밋은 하지 않는다.
